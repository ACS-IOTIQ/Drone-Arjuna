01 — Purpose & Staffing Windows

Two windows, one constraint

This plan sequences every gap identified in the As-Built Implementation Status Report (Phases 3–6) across two staffing windows, built around a single constraint: Vaishnavi's availability drops to a quarter of normal for the first three weeks.

Window A — 10–31 Aug. Vaishnavi at 25% capacity. Chandra Sekhar carries the backend load; Indra runs frontend independently.  ·  Window B — 1–30 Sep. Vaishnavi returns to full capacity — backend work splits in parallel between her and Chandra Sekhar, while Indra continues frontend.

Effort below is costed in person-days (PD) — one PD is one person at 100% capacity for one day. Because Vaishnavi works at 25% through Window A, her elapsed calendar time to deliver a task runs roughly four times its PD estimate.

08 — Risks & Notes

What could move this plan

  • YOLOv8 integration (G5) is the highest-uncertainty item. Model performance on drone-specific imagery is unproven — if accuracy is poor, budget an extra 3–5 PD in late September for retraining, drawn from the G13 load-testing buffer if needed.
  • Vaishnavi's Window A tasks are deliberately paired with Chandra Sekhar's, not independent — 25% availability spread over three weeks makes standalone ownership of anything with an external dependency high-risk for slippage.
  • 3D visualisation (G1) has no backend dependency and is scheduled first in Window A so Indra is never blocked waiting on backend work.
  • The CI pipeline (G11) is intentionally mid-plan, not first — sequencing it once G1 and G4 exist gives it real code paths to lint, test, and build against, rather than standing it up against an incomplete tree.
